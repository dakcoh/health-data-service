## 1. 프로젝트 개요

### 1.1. 주요 기능

- Input Data(JSON) 변환 및 저장
- 시간대별 건강 데이터 관리
- 일별/월별 집계 자동 생성
- 데이터 멱등성 처리 (동일 데이터 재로드 시 업데이트)
- 사용자 인증 (세션 기반)
- Redis 캐싱을 통한 조회 성능 최적화
- 통일된 API 응답 형식
- 전역 예외 처리

### 1.2. 기술 스택

- Java 17
- Spring Boot 4.0.3
- Spring Data JPA (Hibernate 7)
- Spring Security
- Spring Session Redis
- MySQL 8.0
- Redis (세션 저장소 & 데이터 캐싱)

### 1.3. API 엔드포인트

**인증 (AuthController)**
- `POST /api/auth/signup` - 회원가입
- `POST /api/auth/login` - 로그인
- `POST /api/auth/logout` - 로그아웃
- `GET /api/auth/me` - 현재 사용자 조회

**건강 데이터 (HealthDataController)**
- `POST /api/health/load/{fileName}` - JSON 파일 데이터 로드
- `GET /api/health/entries` - 사용자별 건강 데이터 조회

**집계 데이터 (HealthSummaryController)**
- `GET /api/health/summary/daily/{recordKey}` - 일별 집계 조회
- `GET /api/health/summary/monthly/{recordKey}` - 월별 집계 조회

## 2. 프로젝트 구조

```
src/main/java/com/ocare/health/
├── config/          # Redis, Security 등 설정
├── controller/      # API 엔드포인트 (Auth, HealthData, HealthSummary)
├── domain/          # JPA 엔티티 (User, HealthRecord, HealthEntry 등)
├── dto/             # 요청/응답 DTO
├── exception/       # 전역 예외 처리
├── repository/      # Spring Data JPA Repository
├── security/        # 비밀번호 암호화
├── service/         # 비즈니스 로직 (데이터 로드, 집계, 캐싱)
└── HealthDataServiceApplication.java
```

| 패키지 | 설명 |
|--------|------|
| config | Redis 직렬화 설정, 세션 저장소 설정, Spring Security 설정 |
| controller | REST API 컨트롤러 (인증, 건강 데이터 로드/조회, 집계 조회) |

| exception | GlobalExceptionHandler를 통한 통일된 에러 응답 처리 |
| repository | JPA Repository 인터페이스 |
| security | AES 기반 비밀번호 암호화 처리 |
| service | 핵심 비즈니스 로직 (JSON 파싱, 데이터 저장, 일별/월별 집계, Redis 캐싱) |

## 5. 관계 설명

### 5.1. users ↔ health_records (1:N)
- 한 명의 사용자는 여러 개의 건강 기록을 가질 수 있음
- 사용자 삭제 시 관련된 모든 건강 기록 삭제 (CASCADE)

### 5.2. users ↔ health_entries (1:N)
- 한 명의 사용자는 여러 개의 건강 엔트리를 가질 수 있음
- 사용자 삭제 시 관련된 모든 엔트리 삭제 (CASCADE)

### 5.3. health_records ↔ data_sources (1:1)
- 하나의 건강 기록은 하나의 데이터 소스 정보를 가짐
- 건강 기록 삭제 시 관련된 데이터 소스도 삭제 (CASCADE)

### 5.4. health_records ↔ health_entries (1:N)
- 하나의 건강 기록은 여러 개의 시간대별 엔트리를 가질 수 있음
- 건강 기록 삭제 시 관련된 모든 엔트리 삭제 (CASCADE)

### 5.5. 집계 테이블
- daily_health_summary: health_entries를 일별로 집계
- monthly_health_summary: health_entries를 월별로 집계
- record_key로 논리적 연결 (외래키 제약 없음)
- 데이터 로드 시 자동으로 집계 생성/업데이트
- 동일 날짜/월에 대해 재로드 시 값 교체 (멱등성 보장)

## 6. 이슈 및 해결

### 6.1. 데이터 중복 적재 (멱등성)
- 문제: 동일 JSON 파일을 반복 로드하면 health_entries에 데이터가 중복 삽입됨
- 원인: 기존 데이터 존재 여부를 확인하지 않고 매번 INSERT 수행
- 해결: `record_id + period_from + period_to` 조합으로 기존 데이터를 조회하여, 존재하면 UPDATE / 없으면 INSERT 처리. 집계 테이블(daily, monthly)도 동일하게 값 교체 방식으로 변경

### 6.2. Redis ObjectMapper JSON 파싱 오류
- 문제: JSON 파일 로드 시 `WRAPPER_ARRAY` 타입 관련 역직렬화 오류 발생
- 원인: Redis 직렬화용 ObjectMapper에 `activateDefaultTyping`이 설정되어 있었고, 이 ObjectMapper가 JSON 파일 파싱에도 사용됨
- 해결: Redis 전용 ObjectMapper(`@Qualifier("redisObjectMapper")`)와 일반 ObjectMapper(`@Primary`)를 분리하여 각 용도에 맞게 주입

### 6.3. 날짜 포맷 파싱
- 문제: JSON 데이터의 날짜 형식이 파일마다 다름 (`yyyy-MM-dd HH:mm:ss` / `yyyy-MM-dd'T'HH:mm:ssZ`)
- 해결: ISO 포맷을 먼저 시도하고, 실패 시 일반 포맷으로 파싱하는 방식으로 두 가지 형식 모두 지원

### 6.4. 칼로리 데이터 0 값
- INPUT_DATA3, INPUT_DATA4의 모든 칼로리 값이 0으로 수집됨
- 원본 데이터(수집 기기) 자체에서 칼로리 정보를 제공하지 않은 것으로, 코드 이슈가 아닌 데이터 소스의 한계
